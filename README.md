# Звіт до мініпроєкту: Реалізація конвеєра команд у Linux

## Мета роботи
Поглибити розуміння архітектури операційних систем UNIX-подібного типу. Навчитися програмно створювати процеси, керувати міжпроцесною взаємодією за допомогою анонімних каналів (pipes) та виконувати перенаправлення стандартних потоків вводу/виводу.

## Опис реалізації
Розроблена програма мовою C імітує поведінку командної оболонки (shell) при обробці конвеєра: `cat file.txt | grep word | wc -l`.

1. **Ініціалізація каналів:** Батьківський процес створює два анонімні канали за допомогою `pipe()`.
2. **Маршрутизація даних (Процеси):**
   * **Процес `cat`:** Створюється через `fork()`. Читає файл і через `dup2()` підміняє свій стандартний вивід (`STDOUT`) на запис у перший канал.
   * **Процес `grep`:** Підміняє `STDIN` на читання з першого каналу, а `STDOUT` — на запис у другий канал. Виконує фільтрацію за словом "word".
   * **Процес `wc`:** Підміняє `STDIN` на читання з другого каналу. Підраховує кількість рядків і виводить фінальний результат у стандартний термінал.
3. **Обробка помилок:** Для кожного системного виклику (`pipe`, `fork`, `dup2`, `waitpid`) додано сувору перевірку. Якщо виклик повертає `-1`, програма виводить детальне повідомлення про помилку через `perror()` і безпечно завершується.
4. **Управління ресурсами:** Усі процеси ретельно закривають невикористовувані кінці каналів (`close()`), що є критичним для коректного генерування сигналу `EOF` (End Of File) і уникнення взаємного блокування (deadlock).

## Використані системні виклики
* `pipe()` — створення каналів.
* `fork()` — породження дочірніх процесів.
* `dup2()` — дублювання файлових дескрипторів для підміни STDIN/STDOUT.
* `execlp()` — завантаження у пам'ять і виконання зовнішньої утиліти.
* `waitpid()` — блокування батьківського процесу до завершення нащадків.
* `close()` — закриття файлових дескрипторів.
* `perror()` — виведення інформації про системні помилки.
